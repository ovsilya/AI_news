AI_news: architecture

A daily AI-industry brief that runs on GCP and posts to Telegram, plus job-market tracking and a career-fit report. Markets: USA · Canada · UK · Switzerland · UAE. Draft v0.6 · 2026-10-12. Hover a block for a quick tooltip, or click it to see what it does and why.

How the three lanes relate

The lanes are three separate runs of the same container, each on its own schedule. They never call each other: they only read and write the SQLite database. Inside a lane the steps run in order.

  1. ② Jobs (05:00) polls the job boards, extracts new postings and updates the skill statistics.
  2. ① Brief (06:00) reads those results for the brief's career section. The 18:00 run is a lighter update that only covers what changed since morning.
  3. ③ Weekly (Mon 07:00) reads the past week of ① stories and ② postings to compute trends and your market fit, then writes two reports: State of the field and Market fit.

Because the job runs with parallelism 1, only one run at a time can write the database. A run that finds the snapshot locked waits, or fails and retries.

How profile edits work (option B)

  1. You send a plain-text message, voice note, GitHub repo link or PDF in the private chat with the bot. For example: “Shipped an MCP server with FastMCP on Cloud Run”.
  2. The webhook replies “⏳ parsing…” straight away and queues the work in Cloud Tasks.
  3. The input is normalised: voice is transcribed; repo READMEs and dependency files, or PDF text, are fetched and treated as data, never as instructions.
  4. Gemini Flash-Lite receives your current profile JSON and the input, and returns a strict-schema list of add / update / remove changes, each with a reason and evidence. If anything is ambiguous, the bot asks one clarifying question instead of guessing.
  5. The bot shows the diff with three buttons: ✅ Apply · ✏️ Edit · ❌ Cancel.
  6. Apply writes a new profile version in a Firestore transaction. /undo goes back one version and /history lists them. The next pipeline run uses the new version.

The weekly run can also suggest changes, for example “you 👍’d six MCP stories; add MCP = portfolio?”. These come to the same private chat for your approval.

Orchestration

Cloud Scheduler

What: Three cron triggers, which is the free quota: ① the brief at 06:00 and 18:00, ② jobs at 05:00, ③ the weekly reports Mondays at 07:00.

Why: Managed cron with no server to run. Jobs finish before the morning brief, so the brief can include fresh postings.

↑ back to diagram

Cloud Run Job

What: One container image with three modes (run daily | jobs | weekly), 1 vCPU / 2 GiB, parallelism 1.

Why: Pay-per-run, so it fits the free tier. Running a single writer means the SQLite snapshot is never written by two runs at once.

↑ back to diagram

① Daily brief

1 · Ingest

What: Fetches every source, using conditional GET so unchanged feeds aren't re-downloaded. Parses feeds and extracts article text with trafilatura. Records the health of each source.

Why: Incremental fetching keeps runs cheap, and the health check catches feeds that move or die.

↑ back to diagram

2 · Dedup

What: Three passes: canonical URL, then MinHash near-duplicate text, then embedding similarity against the last 72 hours.

Why: The same launch arrives 5–10 times. Each pass is cheap enough to run before the next, so the LLM never sees a duplicate.

↑ back to diagram

3 · Cluster & heat

What: Adds each item to an existing story or starts a new one. Heat counts the distinct sources covering a story, weighted by their authority, and decays over 24 hours.

Why: Stable story IDs let follow-ups attach to yesterday's story. Heat measures importance regardless of your profile.

↑ back to diagram

4 · Score (Flash-Lite)

What: Rules first cut the field to 150–300 stories. Flash-Lite then scores each for relevance, novelty and actionability, and assigns a layer from big picture down to low-level. Your profile sits in a cached prompt.

Why: A cheap model for bulk judgement. A quota per layer keeps the brief broad, not limited to your own role.

↑ back to diagram

5 · Write brief (Gemini 3.8 Flash)

What: Writes the brief from the top stories, given source excerpts as cited documents, plus a career section built from ② data.

Why: Writing the summary is where quality matters most, and it's one call a day, so the strongest model is affordable.

↑ back to diagram

6 · Verify & publish

What: Removes sentences without a citation, checks every number and version against its source, and resolves links. Then posts to the channel with feedback buttons and stores the message IDs.

Why: Summaries have to be trustworthy. The stored message IDs connect each button click to its story.

↑ back to diagram

② Jobs

J1 · Poll & diff

What: Fetches every tracked job board and the SerpApi searches for all five markets, parses new alert emails, and compares the result with yesterday: new, changed and closed postings.

Why: Only new postings need LLM work. Closing dates show how long roles stay open.

↑ back to diagram

J2 · Extract (Flash-Lite)

What: Turns each new posting into strict JSON: role family, skills, frameworks, cloud, seniority, salary, remote policy, plus quotes as evidence.

Why: Converts free text into comparable fields. Cheap enough for hundreds of postings a day.

↑ back to diagram

J3 · Aggregate

What: Normalises skills to a taxonomy and updates skill counts for each market (US / CA / UK / CH / UAE, with remote roles counted separately). Flags postings that match your role, seniority and remote filters.

Why: Precomputed statistics keep the brief's career section and the weekly report fast and cheap.

③ Weekly

W1 · Trends & fit

What: Finds topic bursts against 7- and 28-day baselines and measures skill demand and its week-over-week change. Compares that with your profile to get coverage, missing skills and rising skills.

Why: Answers 'am I keeping up?' with data rather than a feeling.

Storage & platform

Cloud Storage

What: Holds the SQLite database snapshot: downloaded at the start of a run and uploaded at the end, but only if no other run has changed it in between. Also holds the brief archive and weekly profile exports.

Why: SQLite is the simplest database for a single writer, and GCS keeps it durable for free. Writing SQLite directly over GCS FUSE is unsafe because FUSE has no file locking.

↑ back to diagram

Firestore

What: Stores feedback clicks, your versioned profile (skills, projects, portfolio, targets), and bot state such as edits waiting for approval.

Why: The bot is stateless and can run several copies at once, and Firestore handles small simultaneous writes on the free tier. Every run merges this data into SQLite.

↑ back to diagram

tg-bot (Cloud Run service)

What: Receives Telegram updates by webhook: button clicks, commands and profile edits. It acknowledges straight away and hands slow work to Cloud Tasks: transcribing voice notes, fetching repos and PDFs, and the Flash-Lite call that drafts a profile change.

Why: Scales to zero, so it costs about $0, yet buttons respond instantly. Polling Telegram instead would need an always-on instance at about $12/mo.

↑ back to diagram

Platform services

What: Secret Manager for the bot token and keys, Artifact Registry for the image, Cloud Tasks for async bot work, Logging, and a $5 budget alert.

Why: Keeps secrets out of the public repo, adds a cost guardrail, and needs no servers.

↑ back to diagram

Vertex AI

What: Gemini 3.1 Flash-Lite for scoring, extraction and parsing bot edits; Gemini 3.8 Flash for writing (Gemini 3.1 Pro if more quality is needed); gemini-embedding-2; speech for voice notes and an optional audio brief.

Why: One billing account and IAM authentication, with no API keys. Google's own models need no access request, and the global endpoint is about 10% cheaper than regional ones. Claude stays available as an optional provider.

You · private bot chat

What: Option B (decided): describe a change in plain text or a voice note, or send a GitHub link or a PDF. An LLM turns it into a proposed profile change, and you approve or reject it (✅ Apply · ✏️ Edit · ❌ Cancel). Commands: /skills, /gaps, /fit, /jd (paste a job description to see how you match), /undo, /history.

Why: Keeps your skills and projects current from your phone. Every change is previewed before it is applied and versioned, so it can be undone. Only your Telegram account, in the private chat, can edit the profile.
