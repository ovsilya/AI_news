Retrieval methods on this page

Why each source is fetched the way it is. New to these terms? The methods overview starts with a plain-language glossary, then explains how a method is chosen and the rules every collector follows.

RSS / Atom feed

Most blogs and news sites publish a feed: a small file that lists their latest posts (title, date, link) in a standard format. RSS and Atom are two versions of the same idea. Our collector opens that file twice a day and keeps anything it hasn't seen before. It's like subscribing to a magazine instead of walking to the newsstand to check whether a new issue is out. Why we prefer it: the site publishes the feed precisely so that programs can read it, so it is allowed, free, and rarely breaks.

Technical details

How it works: Fetch the publisher's feed with a feed-reader User-Agent and conditional headers (If-None-Match / If-Modified-Since). A 304 reply means nothing changed and costs nothing to parse. New items are recognised by GUID or link and passed to dedup.

Why this method: The feed is the publisher's own machine-readable channel: allowed by design, stable for years, and it gives a clean title, date and link without parsing HTML. One cheap request per source per run.

Watch-outs: Paywalled sites send only a headline and teaser, so the brief links out. A few feeds need a browser-like User-Agent (VentureBeat). Intermittent 404s are retried with backoff.

Search proxy: Google News RSS

Reuters, for example, offers no feed. But Google News lets you save a search ("Reuters articles about AI from the last week") and receive the results as a feed. We use that search feed as a stand-in for the missing one. This is what proxy means here: an indirect route to the same information. Google's links pass through a redirect first, so we follow each one to the original article. Why: it is free, needs no key, and doesn't involve copying the publisher's site.

Technical details

How it works: A saved Google News RSS search, for example site:reuters.com "artificial intelligence" when:7d. Each item links to a news.google.com redirect, which is resolved to the original URL before dedup.

Why this method: For sources without a feed (Reuters) or topics without a single source (UAE AI, US state AI bills), a saved query is the cheapest legal way to get a headline stream: no key and no scraping of the publisher.

Watch-outs: Headlines only. Unresolved redirects would break dedup. Google can change the format, so the health check watches the item count.

Used here by: Reuters AI, US · CA + NY AI bills, UAE · AI news, AI & jobs news

Filtered feed

Some feeds include everything a big organisation announces. AWS, for example, posts dozens of updates a day, most of them unrelated to AI. We read the whole feed but keep only the items whose titles contain words we care about, such as "Bedrock" or "AI". Why: we still catch the important announcements, without paying the AI model to read hundreds of irrelevant ones.

Technical details

How it works: Same as an RSS/Atom feed, then keep only items whose title or category matches a keyword list, for example Bedrock and SageMaker for AWS, Technology and Gulf for Semafor, AI/KI for the Swiss federal news service.

Why this method: Generalist feeds publish dozens of items a day and most are irrelevant. Filtering before the LLM stage keeps scoring cost and noise down, while still covering announcements that appear nowhere else.

Watch-outs: Keyword lists drift. The weekly recall check flags stories we missed, and the list is widened when that happens.

Used here by: Semafor, UK · DSIT, Switzerland · Federal news service, The Pragmatic Engineer, Stratechery

Community scraper feed

For a few sites with no feed, volunteers run an open-source project that checks those sites and publishes a feed for them. We read that ready-made feed instead of building our own scraper. Why: someone else maintains it, at no cost to us. If the volunteers stop, only that one source is affected and we switch to comparing page copies (page diff).

Technical details

How it works: Use an RSS file produced by an open-source project (Olshansk/rss-feeds on GitHub) that scrapes sites lacking feeds and commits the XML to the repo.

Why this method: It provides a feed for blogs that have none (the AISI blog, and Anthropic News as a fallback) without us running a scraper. If it stops, only that one source is affected.

Watch-outs: Third party, so it can go stale. The health check alerts when there has been no new item for a set number of days, and the page diff takes over.

Used here by: UK · AISI blog
