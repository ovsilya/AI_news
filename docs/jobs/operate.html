Run and change the job search

The commands, the files you edit, how to add an employer or change what counts, where everything is stored, and what to do when something looks wrong. Commands run from the repo folder, as .venv/bin/ainews ….

Commands

CommandWhat it does
ainews jobsThe daily run: polls all 129 employers, saves new, changed and closed postings, then the model reads up to 200 unread ones. Prints a summary such as “polled 129 boards (0 errors) … 148 new, 0 changed, 0 closed”
ainews jobs --no-llmPolls only, with no model calls, for free
ainews jobs --only nvidia,tdPolls only these employers (ids from companies.yaml)
ainews jobs --max-extract 50Lets the model read at most 50 postings this run
ainews jobs-probe <slug> …Finds which of Greenhouse, Lever or Ashby an employer uses and prints a companies.yaml line
ainews jobs-probe --workday <tenant> …Lists a Workday tenant's career sites that robots.txt allows, with their open postings
ainews openingsRanks the week's new, unsent postings by fit to you, prints them with their fit, and saves the message to out/openings-<date>.md; nothing is sent
ainews openings --sendBuilds the openings and posts them; each posting is sent once
ainews openings --top 12A longer list this time (the default is top in private/openings.yaml, else 8)
ainews send --openingsPosts the latest saved openings
ainews weeklyBuilds the weekly report (about 1 cent) and saves out/jobs-<date>.md
ainews weekly --no-llmThe report's tables only, without the notes, for free
ainews weekly --sendBuilds the report and posts it to Telegram
ainews send --reportPosts the latest saved report to Telegram
ainews budgetShows model spending against the caps

Add an employer

  1. Find its system. Open the employer's careers page and look at the address of a job: job-boards.greenhouse.io/…, jobs.lever.co/…, jobs.ashbyhq.com/… or ….myworkdayjobs.com/…. Or simply try the probe.
  2. Probe it. ainews jobs-probe acme, or ainews jobs-probe --workday acme, where the tenant is the first part of the Workday address. If the employer has several sites, keep the main one; sites that repeat it add nothing.
  3. Paste the line into config/companies.yaml under the right group. Give it a readable name, and set ai_native: false unless it's an AI company.
  4. Try it: ainews jobs --no-llm --only acme. The summary shows how many postings were listed and kept.
  5. Rebuild these pages so the employer list is current: .venv/bin/python scripts/build_job_pages.py.

Change what counts

  • Another target role family: add it to FAMILIES and a title rule to _RULES in filters.py (order matters: first match wins), add it to the role_family list in the extraction prompt and raise its version, and add it to TARGET in stats.py if it should be in the report's main numbers.
  • Another market: add a code to MARKETS, its place names to _PATTERNS and its two-letter country code to _COUNTRY_CODES in filters.py, and its country names to COUNTRIES in workday.py so the Workday country filter ticks it.
  • A skill that's counted under two names: add the second name as an alias in config/skills.yaml. No re-reading is needed.
  • Workday keywords: QUERIES in workday.py. Each keyword adds up to 10 search requests per site per day.

After code changes, run the tests: .venv/bin/pytest.

Where everything is stored

All in the SQLite file data/ainews.sqlite, which is gitignored. Open it with sqlite3 data/ainews.sqlite.

TableWhat's in it
job_boardsOne row per employer: last poll time, status (ok or the error), postings listed and kept
job_postingsEvery kept posting, open or closed: title, link, places, markets, text, the board's salary, posted date, first and last seen, closed at
job_extractionsThe model's form for each posting, with the prompt version and the text fingerprint it was read from
reportsEvery weekly report (jobs_weekly) and daily openings (jobs_openings): the statistics or the postings picked, the Markdown and Telegram text, message IDs once sent, and the cost
job_alertsEvery posting sent as an opening, with its fit and the report it went out in, so it's never sent twice
snapshotsworkday:<employer>:skipped: Workday postings read before and outside your roles or markets
llm_callsEvery model call: purpose (jobs, weekly…), tokens and cost
runsEvery run: lane, start and end, status, and its counts

Useful questions to ask it:

-- boards that failed on their last poll
SELECT company, last_polled_at, last_status FROM job_boards WHERE last_status != 'ok';

-- open postings per role family (the title's guess)
SELECT title_family, COUNT(*) FROM job_postings WHERE closed_at IS NULL GROUP BY 1 ORDER BY 2 DESC;

-- postings still waiting for the model
SELECT COUNT(*) FROM job_postings p LEFT JOIN job_extractions e ON e.posting_id = p.id
WHERE p.closed_at IS NULL AND e.posting_id IS NULL;

-- open FDE / applied AI postings in the UK
SELECT company, title, url FROM job_postings
WHERE closed_at IS NULL AND title_family = 'fde_applied_ai' AND markets LIKE '%"UK"%';

-- openings sent in the last week, best fit first
SELECT a.fit, p.company, p.title, p.url FROM job_alerts a JOIN job_postings p ON p.id = a.posting_id
WHERE a.sent_at >= datetime('now', '-7 days') ORDER BY a.fit DESC;

-- model spending on job reading this month
SELECT ROUND(SUM(cost_usd), 3) FROM llm_calls WHERE purpose = 'jobs' AND at >= strftime('%Y-%m-01', 'now');

When something looks wrong

You seeWhat it means, and what to do
“polled 129 boards (2 errors)”Two boards failed and were skipped; they closed nothing. The job_boards query above shows why. A 404 usually means the employer moved to another system or renamed its board: probe it again. A timeout usually clears by the next day.
PermissionError: robots.txt disallows …A Workday site's robots.txt no longer allows it, so it's no longer searched. Probe the tenant for another allowed site, or remove the employer.
A warning like “403 Forbidden” for one Workday postingThat one page refused us. It's skipped and tried again next run. Many of them on one site would mean we're being throttled, so lower WORKDAY_WORKERS or MAX_DETAILS.
“281 Workday postings wait for the next run”Normal in the first days: each site reads at most 60 new postings per run.
“extraction skipped: …”Model calls are off (AINEWS_LLM_ENABLED) or not set up. Polling still happened.
“stopped: … cap”A spending cap was reached. Reading resumes on the next run; ainews budget shows where you stand.
The report covers few postingsThe backlog hasn't been read yet. Each run reads 200; run ainews jobs again later the same day to go faster.
No rising or falling skillsExpected for the first 14 days, and in any week with fewer than 30 new target postings.
A job you expected is missingCheck the title with the title tester and the location against the market examples. On Workday, the job must also turn up for one of the 7 keywords; German or French titles (“KI-Ingenieur”) don't.
“no new openings above the fit bar”Nothing new passed your filters with a fit of 50 or more. If it says postings wait for the model, run ainews jobs first; otherwise lower min_fit or widen families, markets or levels in private/openings.yaml.
An opening you don't want keeps its kind comingIts fit comes from your lists: check what it shows under ✅ Yours. Narrow families, add the level to skip_levels, or raise min_fit.
A sentence missing from the notes, with a warningThe number check removed it because it used a number that isn't in the statistics. That's the check working.
