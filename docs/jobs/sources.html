1 · Where postings come from

Every posting comes from the employer's own career system: 129 employers, 97 of them on Greenhouse, Lever or Ashby (35, 5 and 57) and 32 on Workday. These are the same public endpoints the employers' career pages use, so there are no keys and no logins, and none of the job sites whose terms forbid programs.

Two kinds of career systems

The difference that shapes everything downstream: Greenhouse, Lever and Ashby hand over an employer's full list of open jobs in one request. Workday only offers search, 20 results at a time and ranked by relevance, so there is no full list to compare against.

“AI company” or not: why it matters

Each employer is marked ai_native (an AI company) or not. At an AI company, a “Solutions Architect”, “Research Engineer”, “Data Scientist” or “Member of Technical Staff” is almost always an AI role, so these titles count. At a bank or a database company the same titles usually aren't, so they count only when the title itself names AI or ML (“Solutions Architect, GenAI”). 77 of the 129 employers are marked as AI companies, NVIDIA among them.

How a new employer is found: probing

You rarely know which system an employer uses. The probe command tries them for you and prints a line ready to paste into config/companies.yaml:

  • ainews jobs-probe anthropic tries the name on Greenhouse, Lever, Lever's EU instance and Ashby, and reports which answer and how many postings each has.
  • ainews jobs-probe --workday nvidia tries the 9 Workday data centres (wd1, wd3, wd5, wd12, wd10, wd103, wd101, wd105, wd108). On each it reads robots.txt, which lists the career sites crawlers may use (Allow: /NVIDIAExternalCareerSite/). It skips sites named like internships, students, early careers, alumni or private postings, then asks each remaining site how many postings it has.
$ ainews jobs-probe --workday nvidia rbc
  - {id: nvidia, name: nvidia, ats: workday, board: "nvidia.wd5/NVIDIAExternalCareerSite", ai_native: false}   # 2000 open
# rbc: no Workday career site that robots.txt allows

Then you choose: give the employer a proper name, set ai_native, and when an employer has several sites keep the main one. On 13 Oct 2026 the probe tried 70 Workday tenants, and these choices were made:

  • Sibling sites that repeat each other were dropped: Sun Life's and Julius Baer's second sites list the same postings.
  • Different sites that don't overlap were both kept: PwC US and Genentech (on Roche's tenant) are separate from their parents.
  • Low-yield sites were dropped: PwC's global site has no country filter, and only 1 in 60 of its AI postings was in your markets.
  • RBC is out: its robots.txt disallows its main site (Disallow: /RBCGLOBAL1/) and allows only early-talent roles.
  • Not on Workday, or no site that robots.txt allows: Citi, Dell, AMD, Qualcomm, EY, KPMG, Deloitte, Scotiabank, Telus, Shopify, HSBC, NatWest, BP, Vodafone, Sky, BT, UBS, Nestlé, Zurich, Swiss Re, ABB, and the UAE employers tried (G42, ADNOC, e&, Emirates NBD, FAB, Mubadala, Careem). The tenant called lloyds turned out to be Lloyd's of London, not Lloyds Bank.

Staying polite and allowed

  • We say who we are. Every request carries a User-Agent naming the bot and this project.
  • One request a second per site. Each host gets at least a second between requests. The 32 Workday sites run 4 at a time, but each on its own host, so no single site sees more than one request a second.
  • Back off on trouble. A “too many requests” (429) or server error is retried after a pause that doubles each time. A board that still fails is recorded and skipped for the day, and it closes nothing.
  • robots.txt decides. A Workday site that robots.txt doesn't allow is never searched; the run records it as an error instead.
  • Small and steady. A daily Workday run is usually 10–70 search requests per site, plus one request per new posting, at most 60.
